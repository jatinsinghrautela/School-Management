# Browser regression checks

The free, pinned Playwright runner tests the built React application served by the Node API, using a separate in-memory demo server on port 4100. It refuses to reuse another server. Tests use only seeded synthetic accounts; they do not connect to MySQL or change the workspace preview on port 5173. SMTP and upload scanning are explicitly disabled in the test server.

Install dependencies with `npm ci`, install the local browser with `npx playwright install chromium`, then run `npm run test:e2e`. The command builds the web app before starting the isolated server. GitHub Actions installs Chromium and runs the same suite alongside API tests. No hosted testing service or subscription is required. GitHub runner usage remains subject to the repository account's allowance.

Coverage includes built-app script errors, desktop logout visibility at 1280 × 800, mobile menu/logout and horizontal overflow at 390 × 844, dialog focus entry/wrapping/Escape/restoration and scroll locking, assigned-school switching, teacher notice targeting, disabled resource uploads and student read-only actions.

Five additional accessibility tests use the pinned free axe-core checker with WCAG 2 A/AA and 2.1 A/AA rule tags. They scan desktop/mobile login, owner/principal/teacher/student dashboards, school-role notice screens and principal/teacher publishing dialogs. Scans fail on any detected violation; rules are not excluded to hide failures. Automated checks cannot establish complete WCAG conformance.

Failure traces are saved under ignored `test-results/`. Open a specific trace with `npx playwright show-trace <trace.zip>`. Keep these checks synthetic; traces can contain page content and must not be collected against real student records.

This suite complements API and isolated MySQL checks. It is a Chromium regression baseline, not a complete accessibility audit, cross-browser certification or production deployment acceptance. Screen-reader review, further contrast coverage, additional viewport/content combinations and actual HTTPS proxy testing remain release work.

Appearance checks verify the two-state scene switch, initial/live system preference, remembered explicit choice, responsive headers at 320/390/768 pixels, and axe contrast scans of login, every principal navigation page and publishing dialogs in both Light and Dark modes. These use seeded data and do not establish complete accessibility conformance for every possible record or workflow. School branding and school-switch checks remain in place.

Phase 4 expands this baseline to three engines: install `chromium firefox webkit`, then run `npm run test:browsers`. The default `test:e2e` stays Chromium-only. The matrix applies the same suite to all engines with one worker and isolated demo data; the privacy test covers password-confirmed download, requester-only review UI, dark accessibility and mobile overflow. Use `npm run test:browsers -- --project=webkit` to isolate one engine. GitHub Actions installs all three. WebKit is an engine regression check, not a certification of every real Safari/iOS device; manual screen-reader/HTTPS review remains required.

The default matrix gives each engine a separate process/server and trace output folder, so fixture mutations and repeated authenticated reads cannot exhaust a limiter shared by all three runs. Production authentication limits are unchanged. Appearance fixtures also set Firefox's native system color preference; page-level emulation alone was lost on protected initial navigation. Live media changes remain tested, every appearance scan asserts its actual light/dark state, and no security headers or accessibility rules are disabled. The expanded real-dark scan found an unsupported dropdown pseudo-selector invalidating the whole dark input rule in Firefox; the optional picker rule is now isolated with `@supports`.

The initial native Firefox bundle on C: failed with a side-by-side `mozglue` assembly error while the system drive was full. Reinstalling on the project's D: drive restored browser launch. On this workspace, set `$env:PLAYWRIGHT_BROWSERS_PATH = 'D:/Personal Projects/School Management/apps/api/data/browsers'` before installing or running browser/release checks. This location is ignored by Git. WebKit revealed a real pointer-opener focus-restoration issue; the shared dialog hook now records the opening control and distinguishes keyboard actions. The optional container fallback failed to download because Docker's system-drive storage became read-only; it is not marked accepted.
